# План MVP: воксельная игра (Rust + Bevy)

## Решения

- **Движок:** Bevy 0.19 (ECS).
- **Скоуп MVP:** бесконечный мир + ломать/ставить блоки. Без выживания/инвентаря/сохранений/дня-ночи.
- **Мультиплеер:** в MVP не пишем, но симуляция отделена от рендера, чтобы сеть встала между ними без переписывания.
- **Тулинг:** максимум — юнит-тесты ядра, инструменты отладки, CI с первого коммита.
- **Компромиссы/ограничения:** фиксируются в [`docs/tradeoffs.md`](tradeoffs.md).

## Архитектура

### Принцип: вся логика — библиотеки, бинари — тонкие

- **Логика живёт только в lib-крейтах** (`crates/`). Бинари (`apps/`) содержат только `main.rs` и не несут логики.
- Отсюда: **«сервер» — это библиотека** (`server-core`), а не бинарь. Тогда `apps/server` = тонкий `main.rs` (`server_core::run()`), а клиент встраивает сервер просто зависимостью на `server-core` и запуском в фоне.
- **Клиент тоже lib + тонкий bin**: бинари почти не покрываются интеграционными тестами, а lib — покрывается. Плюс логику клиента можно тестировать без запуска окна.

### Раскладка (MVP)

```
one_of_two/
├── Cargo.toml            # workspace: [workspace.package], [workspace.dependencies], [workspace.lints]
├── rust-toolchain.toml   # пин канала + components
├── rustfmt.toml / .editorconfig / .gitignore
├── Justfile
├── .github/workflows/ci.yml
├── crates/               # переиспользуемые библиотеки (вся логика)
│   ├── simulation/       # ЧИСТАЯ логика мира, БЕЗ Bevy (server-ready)
│   │   ├── coord.rs      #   BlockPos / ChunkPos + конвертации
│   │   ├── block.rs      #   BlockId, BlockRegistry, свойства блока
│   │   ├── chunk.rs      #   Chunk (palette-хранилище)
│   │   ├── world.rs      #   World (карта чанков, get/set блока)
│   │   ├── gen.rs        #   детерминированная генерация террейна
│   │   ├── raycast.rs    #   DDA voxel raycast
│   │   └── collision.rs  #   AABB против вокселей
│   └── client/           # Bevy-клиент как lib (presentation)
│       ├── mesh.rs       #   чистый мешер (face culling) — тоже тестируется
│       ├── render/       #   материал + текстурный атлас
│       ├── stream.rs     #   стриминг чанков вокруг игрока
│       ├── interaction.rs#   подсветка + ломать/ставить
│       └── debug/        #   egui-панель, границы чанков, FPS
└── apps/                 # тонкие бинари (только main.rs, без логики)
    └── client/           #   client_lib::run()
```

### Рост (будущее)

```
crates/
├── simulation/    # мир, чанки, ген, коллизия
├── protocol/      # сериализованные сообщения (общее для клиента и сервера)
├── server-core/   # авторитетный цикл сервера (симуляция + сеть)
├── client/        # Bevy-клиент (lib)
├── meshing/       # если вынесем чистый мешер из client
└── assets/        # блоки/атлас, общие определения
apps/
├── client/
└── server/
```

**Почему так:** `simulation` не знает про Bevy, детерминирован и полностью покрыт юнит-тестами — это будущий «сервер». `client` только читает/мутирует `World` через его публичный API. Сеть потом встанет между ними без переписывания. Мешинг — презентация, но он чистый (функция «чанк → буферы») и живёт в отдельном модуле `client` со своими тестами.

**Заметки по раскладке:**

- Cargo не завязан на структуру: `members = ["crates/*", "apps/*"]`, путь-зависимости ссылаются на относительные пути. Переезд дёшев.
- Не заводить `common`/`util` заранее — превращается в свалку; только узкие крейты (`protocol`, `meshing`) по реальной необходимости.
- `apps/` вводим сразу (клиент — бинарь с первого дня), но второй бинарь `server` появится только вместе с `server-core`.

## Ключевые проектные решения

| Вопрос | Решение | Обоснование |
|---|---|---|
| Размер чанка | Кубический **16³** | Равномерная математика, проще стриминг |
| Высота мира | Море 64, поверхность ~8..160; горизонтально — бесконечность. В будущем минимальная высота мира **-128** (глубокие пещеры, как в новых версиях Minecraft), максимум ~256 | Проще террайн-ген; переход на отрицательный `y` позже не затронет хранилище |
| Хранение блоков | `Chunk { palette: Vec<BlockId>, data: [u8; 4096] }` | Память + подготовка под save/load; индекс 0 — всегда air |
| Тип блока | `BlockId(u16)` + `BlockRegistry` | Отделяет данные блока от мира, легко расширять |
| Деление координат | Только `div_euclid`/`rem_euclid` | Корректная работа с отрицательными координатами — классический источник багов, тестируем явно |
| Террайн-ген | `noise` 0.9 (fBm/Perlin), seed: `u64` | Детерминированность → воспроизводимость и тесты |
| Мешинг | Face culling (жадный — потом) | Проще, корректнее, покрываемо тестами; greedy — оптимизация на потом |
| Атлас текстур | Процедурный (генерация в коде) | Нет бинарных ассетов в репо, детерминированно, нет asset-пайплайна на старте |
| Физика | Свой AABB-коллижн против вокселей | Чистая логика → в `simulation`, тестируется; без тяжёлой физики |
| Логи | `tracing` + `tracing-subscriber` (env-filter) | По-модульный уровень, тайминги |
| Профилирование | Bevy feature `trace_tracy` + Tracy | Дешёвая интеграция, реальные данные |

Пины: `bevy = "0.19.1"`, `bevy_egui = "0.42"`, `bevy-inspector-egui = "0.37"`, `noise = "0.9"` (версии `bevy_egui`/inspector сверять с bevy 0.19 в момент имплементации).

## План по коммитам (каждый — зелёный CI, маленький, с тестами)

### Фаза A — Workspace + тулинг (коммиты 1–6)

1. **Гигиена проекта** — `.gitignore`, `.editorconfig`, `rustfmt.toml` (единый стиль).
2. **Workspace** — корневой `Cargo.toml`: `[workspace]`, `[workspace.package]`, `[workspace.dependencies]` (все версии в одном месте), `[workspace.lints]` (clippy `pedantic`+избранные, `rustdoc`). `members = ["crates/*", "apps/*"]`. Пустые крейты `crates/simulation` (lib), `crates/client` (lib) и `apps/client` (bin).
3. **`rust-toolchain.toml`** — пин канала + `rustfmt`, `clippy` (воспроизводимые сборки на всех машинах).
4. **`Justfile`** — `just` (default = список) + `fmt` / `fmt-check` / `check` / `clippy` / `test` / `doc` / `run`. Набор сокращён (`test-core`/`run-release`/`profile`/`bench` — добавим по необходимости).
5. **CI** — `.github/workflows/ci.yml`: `ubuntu-24.04`, `dtolnay/rust-toolchain` (читает `rust-toolchain.toml`, без дублирования версии), `taiki-e/install-action` (just), `Swatinem/rust-cache`; шаги `just fmt-check / clippy / test / doc`. Branch protection на `master` включается вручную.
6. **Hello-world** — `apps/client` (тонкий `main.rs`) открывает пустое Bevy-окно через `crates/client::run()`; `crates/simulation` — первый тест; Bevy 0.19.1 (default features). В CI добавлен apt-шаг для системных зависимостей Bevy на Linux.

### Фаза B — Ядро симуляции (коммиты 7–11)

7. **`coord.rs`** — `BlockPos`, `ChunkPos`, `LocalPos` (i32), константы `CHUNK_SIZE`, конвертации `block ↔ (chunk, local)` через euclid + юнит-тесты (положительные/отрицательные/границы).
8. **`id.rs` + `block.rs`** — `ResourceId` (`namespace:path`), `BlockId(u16)` (непрозрачный), `Block` (solid/opaque), `BlockRegistry` (register/get/get_id, резервы `AIR`/`UNKNOWN`), `BuiltinBlocks` (типизированные id) + тесты.
9. **`chunk.rs`** — `Chunk` (palette + `[u8; 4096]`), `get`/`set` блока, `to_index` + тесты (границы, round-trip).
10. **`world.rs`** — `World { seed, chunks }` на `hashbrown::HashMap<ChunkPos, Chunk>` (быстрый хешер `foldhash`). `get_block -> Option<BlockId>` (`None` = чанк не загружен) и `set_block -> bool` (чанки создаются только явно через `insert_chunk`) + тесты.
11. **`gen.rs`** — `TerrainGenerator` (детерминированный heightmap через `noise` 0.9), `height_at(x,z)` + `generate_chunk` (трава/земля/камень/песок/вода); типизированный `BuiltinBlocks` + тесты (детерминизм, разные seed'ы, диапазон высот, слои колонки).

### Фаза C — Ранний рендер и навигация (коммиты 12–20)

Сначала видим мир и летаем, потом взаимодействие.

12. **App-каркас** — `client::run()` (App setup), камера + clear color.
13. **Первый воксель** — хардкод-чанк → меш → рендер.
14. **Процедурный атлас** — текстура атласа, материал, UV-маппинг граней (разные цвета на грани).
15. **`mesh.rs`** — мешер face-culling: `Chunk → {positions, normals, uvs, indices}` (u32) + юнит-тесты (внутренние грани не эмитятся, счёт вершин корректен).
16. **Рендер мира** — генерация и рендер области вокруг точки через мешер.
17. **Стриминг** — генерация/мешинг на `AsyncComputeTaskPool`, вставка мешей по мере готовности.
18. **egui-панель** (FPS + число загруженных чанков) — выносим рано, упор на отладку.
19. **Анлоад** — выгрузка чанков за радиусом отрисовки.
20. **First-person камера** — WASD + мышь (look), полёт **без коллизий**.

### Фаза D — Взаимодействие (коммиты 21–23)

21. **`raycast.rs`** — DDA voxel raycast: `(hit: BlockPos, face: Direction)` + таблица тестов (луч вдоль осей, диагонали, сквозь прозрачные блоки).
22. **Подсветка блока** — DDA-луч из центра экрана → подсветка выбранного блока (wireframe/gizmo).
23. **Ломать/ставить** — ЛКМ = сломать, ПКМ = поставить; `World::set_block` (API мутации отдельно не нужен) + ремеш затронутых чанков.

### Фаза E — Физика и доводка симуляции (коммиты 24–26)

24. **`collision.rs`** — AABB против вокселей (движение с разрешением по осям) + тесты; подключаем гравитацию/ходьбу к камере.
25. **Интеграционные тесты** — `tests/world_integration.rs`: set/get через границы чанков, ген-детерминизм.
26. **Документация** — `#![warn(missing_docs)]` включён, документировать публичный API, `cargo doc` зелёный в CI.

### Фаза F — Инструменты отладки (коммиты 27–30)

27. **Границы чанков** — оверлей через Bevy-гизмо (toggle).
28. **`bevy-inspector-egui`** — инспекция состояния стриминга/мира в рантайме.
29. **`tracing`** — env-filter, по-модульные уровни, тайминги мешинга/генерации.
30. **Профилирование** — `trace_tracy` + `just profile`, разметка hot-путей.

### Фаза G — Харденинг и полировка (коммиты 31–35)

31. **Clippy pedantic** — чистка предупреждений, доки, `cargo doc` в CI.
32. **CLI-аргумент seed** — мир генерируется из seed из командной строки.
33. **Бенчмарки** — `benches/` (criterion) для мешинга и генерации (защита от регрессий производительности).
34. **README** — сборка/запуск/тесты, обзор архитектуры.
35. **Финальный прогон** — локально весь CI, тег `v0.1.0-mvp`.

## Стратегия тестирования

- **Юнит-тесты** в `simulation` — покрывают все чистые алгоритмы (координаты, чанки, world, ген, raycast, collision). Это ядро, где скрывается 90% багов воксельных игр.
- **Мешер** в `client` — тоже юнит-тестируется (не зависит от Bevy).
- **Интеграционные** — сквозные сценарии мутации мира.
- **Проперти-тесты** (не решено, `proptest`) — round-trip для `coord`/`chunk`, ловят off-by-one. Решение отложено.
- **Бенчмарки** (criterion) — мешинг/ген как регрессионная защита.
- **Детерминизм** — отдельный тест, что мир с одинаковым seed идентичен.

## Риски

1. **Версии экосистемы Bevy** — `bevy_egui`/`bevy-inspector-egui` должны строго соответствовать bevy 0.19; проверить в момент имплементации (возможны сдвиги).
2. **Статтеры стриминга** — решается асинхронным мешингом (коммит 17); если останется — greedy meshing позже.
3. **Детерминизм `noise`** — зафиксировать точные параметры fBm в тестах, не полагаться на порядок вычислений.
4. **Скоуп-крип** — выживание/инвентарь/сохранение/день-ночь сознательно ВНЕ MVP; добавим отдельными фазами.
